# 「把 AI 想明白」系列风格指南

版本 v1.0（2026-10-01）。本指南约束「把 AI 想明白」系列七篇文章的命名、术语、文风、结构与衔接，写作与发布自查都以此为准。

写成依据三样东西：

- 内容与立意：`AI.md`（主线与写作原则）、`AI学习文章-完整版资料收集大纲（含知识点+检索词+学习资源+优先级）.md`（核心写作立意、素材分工与学习资源清单）；
- 站点约定：`README.md`「如何写新的文字内容」一节（articles.js 字段、深链、gen-rss、SW 缓存版本）；
- 文风样本：`js/articles.js` 的 flash-vbmeta-trust-chain（技术手记代表）与 two-years-of-flashing（随笔代表），其余五篇手记旁证。

## 一、系列名与命名规范

### 系列名：把 AI 想明白

- 全系列对外名称「把 AI 想明白」，共七篇。名字取自系列立意——不神化、不焦虑，把概念、原理、路径、边界一件件想清楚再下判断，与两份大纲「拒绝单纯吹捧、突出行业复合型路线」的要求同源。
- 系列名不进每篇标题。标题带中文数字序号「一、…七、」即可识别归属；系列名只用在首篇导语、篇尾衔接句和对外介绍里。
- 站点没有系列/专栏功能（README 功能清单里无对应字段，不编造新约定），系列识别靠三件事：标题序号、category「AI 学习」、篇尾衔接句。

### 七篇题目总表

slug 即 articles.js 的 `id`，深链 `?post=slug`。

- ai-concepts-primer → 一、Token 是什么：把 AI 圈最容易用错的几个词说清楚 → 纠偏大众误区：区分 AI 与大模型、基座与对话模型、弱 AI 与 AGI，把 Token、上下文窗口、温度系数这些高频词一次讲透，并点破「产品宣传」与「学术定义」的差别。
- ai-model-training → 二、大模型是怎么炼成的：从数据清洗到人类对齐 → 拆数据清洗→预训练→监督微调→RLHF 的流水线，讲清对齐与越狱的关系、训练算力与推理算力的差别，以及中文数据缺口等训练困境。
- ai-learning-paths → 三、学 AI 要不要先啃高数：普通人现实可走的四条路 → 算法研发、大模型工程落地、AI 产品与业务方案、行业复合四条路分层说门槛，附通识学习资源（吴恩达、李宏毅等）与避坑（速成班、裸啃论文）。
- ai-agent-boundary → 四、Agent 为什么会翻车：智能体的能力边界在哪 → 讲思考—计划—工具调用—复盘的闭环与记忆机制，直说规划幻觉与误调工具，捎带云端、本地、私有化三种部署形态；结论是现阶段别神化智能体。
- ai-china-landscape → 五、中国 AI 的长板与短板：为什么落地快、原创少 → 政策、产业链、场景与工程师红利，对撞芯片、数据、底层理论与开源话语权短板，对照中外「通用大模型冲刺」与「产业落地优先」两条路线。
- ai-jobs-rethink → 六、AI 会抢走谁的饭碗：为什么不必都挤向开发岗 → 用电力、制造、矿山、法务财会等落地案例论证：新增 AI 岗小众、存量岗升级是主流，行业积累加 AI 工具的复合型人才最缺。
- ai-frontier-mirror → 七、AI 的下一程：算力的账、走出屏幕的智能与治理的规则 → 算力能耗与液冷绿电、云边端协同与具身智能的走向、风险清单与全球治理博弈，收束全系列回到终身学习。

### 标题规则

- 结构照站点现有「具象问题：实质解答」式（js/articles.js:31「刷机为什么会卡开机：验证启动的信任链从哪开始」）：冒号前是读者认识的钩子（疑问、具体名词），冒号后是本篇的实质内容或判断。
- 序号用中文数字加顿号（一、二、……七、），不用「01」「第 1 篇」。
- 禁口号式大标题：「AI 时代生存指南」「你不了解的 AI」这类看不出内容的题目一律不要；题目必须能看出本篇具体回答什么。
- 标题里可用英文原词作钩子（Token、Agent），正文首次出现时仍按术语表给中文译名。
- 标题控制在 24 字上下，冒号两段各 8～14 字为宜。

## 二、读者与叙述声音

- 叙述者是一个正在学 AI 的学生（博主本人）：以「我学到／我踩过／我判断」的口吻写，不是教师口吻，不是科技媒体口吻。
- 两类读者都要照顾：
  - 普通读者——每个术语首次出现给一句人话解释加一个具体例子。范本照 js/articles.js:141 讲 9008 的写法：「9008 是高通平台最底层的通道，绕开系统直接操作存储芯片，砖了也能救回来」；
  - 同行——靠判断、数据和行业事实给增量，不复述他们已知的东西。
- 立意主线必须立住（两份大纲一致要求）：拒绝神化 AI、拒绝就业焦虑；优势与短板并陈；核心判断是「不必扎堆 AI 开发岗，深耕行业叠加 AI 工具的复合型路线更宽更稳」。
- 第一人称经验是本系列的通行证：每篇至少一处写自己真实的学习或使用经历当例子。编造经历比没有经历更糟。
- 站点互动（批注、情绪反馈、RSS）决定了文章会被单独转发阅读：每篇信息自足，不依赖读过上一篇才能懂。

## 四、文风规则（核心是反 AI 味）

以下每条都从 articles.js 现有文章里提炼，不是通用写作建议。

### 4.1 硬性禁用

- 套话：让我们、总而言之、综上所述、值得注意的是、众所周知、不难发现、由此可见。
- 结构腔：「首先／其次／再次／最后」机械推进；每两三段就立一个小标题；空洞排比（「AI 是工具，是伙伴，也是未来」式）。
- 预告腔：敬请期待、下一期更精彩、「本文将介绍」。
- 感叹号：全系列不用，语气靠内容（现有九篇文章正文没有一处感叹号）。
- 伪互动开头：「你有没有想过……」式钩子。
- 格式：**正文不用代码块，不用反引号**——模型名、参数名（Temperature、LoRA、Top-P）直接写；确需提到命令或语法时用文字描述。

### 4.2 开头

- 首段无标题，两三句进入具体场景、亲身经历或一个反直觉现象。范本 js/articles.js:88：「一开始我以为 root 就是拿到最高权限。后来发现真正麻烦的是『别人知道你拿到了』」。
- 禁背景铺垫：「随着 AI 的飞速发展」「在当今时代」式开头一律不要。
- 首篇（概念篇）可在开头加一小段系列导语：三四句话交代系列来历与七篇的推进（词—炼法—路—边界—格局—饭碗—远处），写成段落不用列表；后续六篇不重复目录。

### 4.3 段落与节奏

- 长短错落：三五行的解释段之后，接一两句的短段作转折或补充。范本 js/articles.js:44：「另一种情况更麻烦：机器能通电，但卡在厂商 logo 反复重启」。
- 关键判断写成加粗句放段首，统领本段。范本 js/articles.js:50–54（「写进去这条路不止一条。」「认不认，看的是验证启动这条链。」）。一篇加粗 8–12 处为宜，不整段加粗，不为强调碎用。
- 段间衔接用口语转折：「另一种情况是」「真正麻烦的是」「这里其实是两件事」（js/articles.js:48）。
- 设问允许用来推进，但一段内不连环设问，设问之后必须自己给答案。范本 js/articles.js:56 的「这就是为什么同一个『刷 boot 拿 root』的动作，在新设备上要换成 init_boot」。

### 4.4 判断与分寸

- 敢下判断，判断落在具体句子里。范本 js/articles.js:271「默认参数假设的是『显存够用』，我这台不是」；js/articles.js:74「不是怕刷坏，是知道坏了有路可退」。每篇至少一处明确表态。
- 判断必须带理由或例子；给不出理由的判断改成疑问句，或者直说「我拿不准」「没查到可靠数据」——承认不确定不丢人，硬编结论才丢人。
- 引数字必须能溯源，正文里点名来源（如「信通院白皮书里写……」）；查不到可靠来源的数字宁可不写。来源优先级照大纲：官方白皮书 > 工信部／信通院公告 > 权威媒体深度报道 > 技术社区 > 自媒体（慎用）。
- 优劣并陈是硬要求：讲优势必带短板，讲短板必承认进展，禁止单边吹捧或单边唱衰（AI.md 写作原则原文：「兼顾优势与现存短板，拒绝单纯吹捧」）。
- 匿名贬损不写：批评培训班乱象、自媒体贩卖焦虑时，描述现象与套路，不点名骂人。

### 4.5 概念怎么讲

- 每个概念「一句话定义 + 一个具体例子或类比」，不许裸定义连排。
- 一个类比用一次就收，不围绕它铺满全篇。
- 学术定义与商业化产品分开说（大纲要求）：「产品里的 AI 功能」和「AI 本身」不是一回事，混淆处要当场点破。
- 误区素材优先用大纲整理好的三类：AI 有自我意识、大模型等于完整 AI、AI 输出全是事实；讲的时候落到具体场景，不抽象罗列。

### 4.6 标点与排版

- 直角引号「」，破折号——，书名号《》用于课程与书（《AI for Everyone》《动手学深度学习》）。
- 中文与英文、数字之间留半角空格（「刷 boot 拿 root」「高通平台上的 9008 模式」，js/articles.js:42、50）。
- 数值与中文单位之间留空格（13 GB、8.8 寸），与英文单位紧跟（60Hz、15.6ms）——与现站文例一致，不强改旧文。
- 正文小节标题层级从 `###` 起，一篇 3–6 个；列表只用于并列项与误区节，每条是完整判断句，不是词组。

## 五、单篇结构与篇幅

- 篇幅：正文 3000–4500 汉字（content 字段内的汉字数，不含 Markdown 符号与英文单词）。低于 3000 讲不透，超过 4500 必须砍——砍例子不砍判断。
- 骨架：借现有手记「问题—方案—踩坑—结论」的推进逻辑（js/articles.js:38–74），但小节标题用具象短语，不硬套四字：
  1. 开场段（无标题）：具体场景或经历 + 一个反直觉的判断；
  2. 2–4 个 `###` 小节：每节解决一个子问题，节内以加粗判断句开头的段落推进；
  3. 一节误区／反例：编号列表 3–5 条，每条先立错误认知再给纠正，素材取大纲的「认知误区」「避坑」清单；小节标题具象（如「### 三个常见误区」）；
  4. 结尾小节：标题具象（「### 回到开头」「### 我的判断」均可，不用「总结」）；中心判断句加粗，落一两句个人态度，再接系列衔接句（见第六节）。
- 延伸说明用折叠注解块（原生 details/summary，README 已支持），别把正文撑爆。
- 学习资源按名称与去处写（「B 站搜李宏毅」），不堆链接列表；确需链接时用普通 Markdown 链接，不贴裸 URL。

## 六、系列衔接

- 每篇结尾用一两句自然引出下一篇：写出下一篇要回答的具体问题，放在末段里，不单独成节，不写「下一篇将介绍」。
- 最后一篇不引出下一篇，改为收束全系列：用两三句把七篇主线串起来（词—炼法—路—边界—格局—饭碗—远处），落回个体的终身学习与自己的态度，不喊口号。

建议衔接句（可改写，保持「落具体、不预告腔」）：

1. 概念篇 → 训练篇：词说清了，模型本身还是个黑箱。下一篇拆开这条流水线——数据清洗、预训练、监督微调、RLHF，看看大模型到底是怎么炼成的。
2. 训练篇 → 路径篇：看完炼模型的过程，反而更容易想明白一件事：炼模型轮不到普通人操心。下一篇说点更实际的——想学 AI，路怎么选。
3. 路径篇 → Agent 篇：四条路走到哪条都会撞见同一个新词：Agent。工具生态都在往智能体上堆，下一篇先不夸它，先看看它现在会什么、不会什么。
4. Agent 篇 → 中国篇：智能体只是工具生态的一角。把镜头拉远，下一篇看看这些技术在中国这块土地上长成了什么样——长板是什么，坎在哪里。
5. 中国篇 → 就业篇：产业的事说到底还是人的事。下一篇落到就业上：AI 到底会抢走谁的饭碗，以及为什么我的答案不是转行做算法。
6. 就业篇 → 前沿篇：岗位之外还有更远处的问题——算力的账怎么算、AI 什么时候走出屏幕、规则由谁来定。下一篇是系列收尾，把这些放在一起看。
7. 前沿篇（收尾）：不引出下一篇；回望七篇主线，落回终身学习与个人态度。

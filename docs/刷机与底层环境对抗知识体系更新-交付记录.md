## 2. 核心增补与技术进阶体系

### 2.1 启动信任链与设备形态四分法 (`posts/flash-vbmeta-trust-chain.md`)
传统刷机教程通常停留在「解 BL ➔ 刷 boot ➔ 关 AVB 校验」的单一路线上。本次更新补全了现代 Android 设备真实的四种启动链信任状态：

1. **真解锁设备（True Unlocked）**：
   - ABL（Android Bootloader）解锁标志被物理置位，放行未经校验的底层分区；
   - 系统属性显示 `ro.boot.flash.locked=0`（orange 警告），硬件 KeyMint 凭据如实反映解锁状态。
2. **自签设备（Self-Signed Devices）**：
   - 如联想拯救者 Y700（二/三/四代）。启动链底层信任公开的 AOSP testkey；
   - 用户用已知私钥重签改动后的 `init_boot` 和 `vbmeta`，在 Bootloader 原厂完全锁定的状态下即可通过校验并以安全绿标开机。
3. **假回锁设备（Fake Lock）**：
   - 如彻底关闭官方 BL 解锁通道的高通平台机型；
   - 在 Bootloader 引导极早期（早于系统与 TEE 固化状态前）植入内存 payload（如 hnubl、gbl_root_canoe、efisp），把内存中的解锁标志改写为 `locked & green`，骗过系统与硬件 TEE 校验，同时加载已修补的内核。
4. **免解设备**：
   - 依赖运行时内核或用户态提权漏洞（常伴随 SELinux permissive），重启即失效。

### 2.2 A/B 双槽机制与保留锁态 OTA 升级协同
针对假回锁设备在官方推送 OTA 时的致命痛点（官方更新覆盖 ABL 导致假回锁丢失或锁态冲突变砖），提炼了不可逾越的**双保险协同次序**：
- **引导锁态归专用工具管**：官方 OTA 安装完成提示重启时**坚决不重启**，先用引导维护工具（如 `hnubl`）对备用槽位的 ABL 和 efisp 打入假回锁补丁；
- **内核权限归 KernelSU 管**：再进入 KernelSU 界面点击「安装到未使用的槽位（OTA 后）」，把 root 补丁写入备用槽位的 `init_boot`；
- **两头就绪后再切槽重启**。

### 2.3 现代风控侦察与内核级隐匿对抗 (`posts/root-hiding-layers.md`)
更新全面升级了检测方与防守方的攻防维度分析：

1. **检测方的底层侦察武器库**：
   - **绕过 libc，直发裸系统调用**：现代高强度检测（春秋检测、银行金融 SDK 等）直接嵌入内联汇编 `SVC #0`，绕过所有用户态 Inline Hook 和 PLT 拦截，直接向内核索取 `/proc/self/maps` 和 `/proc/self/mountinfo`；
   - **挂载点与 VFS 特征扫描**：扫描 overlayfs、tmpfs 的挂载痕迹；
   - **SELinux 策略与 AVC 审计**：检查 SELinux Permissive 状态及自定义 policy 注入。
2. **防守方的深度下沉机制**：
   - **用户态隔离（Zygisk & Shamiko）**：单进程创建 Mount Namespace 还原挂载；
   - **内核级授权与 VFS 抹除（KernelSU + SusFS + FUSE Hide）**：内核态通过 prctl 钩子直接向白名单 UID 派发权限，非授权 UID 执行 `su` 直接返回 `not found`；配合 SusFS 直接在 VFS 层面抹除挂载点、重定向路径并伪造时间戳，彻底防御 `SVC #0` 裸系统调用探测；
   - **硬件级 Attestation（KeyMint / TEE）的分水岭**：解析 Play Integrity 的 Basic、Device、Strong 三级差异，剖析为什么纯软件 `keybox.xml` 无法绕过 Strong 硬件私钥签名，而假回锁设备能在硬件级保留受信任的绿标。

### 2.4 系统属性一致性与原生态保持
手记中补充了底层环境稳定性的关键准则：
- **避免属性撕裂**：避免在全局范围粗暴使用 `resetprop` 改写系统核心参数，防止 Java 上层与 Native 底层驱动、硬件抽象层（HAL）产生数据不一致；
- **最佳实践**：系统全局属性坚决保持原生真机纯净，不做无意义的全局修改，确保系统跨层调用的一致性与稳定性。

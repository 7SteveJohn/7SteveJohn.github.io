# 项目文档与重点手记内容深度去膈应优化 - 交付记录

## 1. 优化背景与重构定位

在完成卡片摘要重构后，用户进一步指示：“文档内容也看看能不能修改”。

经深度排查，发现各项目弹窗的技术难点（`challenge`）、技术规格详情（`details`）以及与之对应的技术手记（`posts/*.md`）正文中，仍存在较多早期的**情绪化诉苦、街头口语、做作假拟人、不严谨夸大**等表达（如“互相打架”、“动错了系统就废”、“文件不能出门”、“把图里的字抄出来”、“跑分多少不重要”等），与个人站冷静、客观、硬核的独立工程师调性产生冲突。

---

## 2. 深度优化核心修改点

### 2.1 项目技术难点（`challenge`）去粗糙化
- **FileButler**：
  - 旧：“难点是「搜得快」和「撤得回」互相打架：几万份文件要秒级出结果，但整理动作必须能反悔……后台空闲时慢慢建……”
  - 新：“核心挑战在于高频检索响应与破坏性整理可逆性之间的架构平衡。解法是建立双轨索引分工：文件名与长文本构建 SQLite FTS5 倒排索引保障即时匹配，文档语义向量化（bge-m3）交由后台线程在系统空闲时增量构建；文件移动操作前强制生成计划清单供人工确认，底层基于事务日志记录元数据，异常或撤销时按批次原子回滚。”
- **NetOps Handbook**：
  - 旧：“把所有常规方案都否掉了……随包带走……索性不申明 INTERNET 权限，从系统层面断掉联网可能，而不是靠自觉。”
  - 新：“核心约束在于完全断网离线环境下的架构闭环：常规的 CDN 依赖、在线检索与动态更新链路均不可用。解法是将全部业务模块、矢量图表与交互样式编译打包为单一离线页面；针对 file:// 协议下浏览器 History 行为的非确定性，自主实现内部导航栈；Android 壳层在 Manifest 中直接剔除 INTERNET 权限，从系统沙盒层彻底杜绝网络外联。”
- **GameBoost**：
  - 旧：“动错了系统就废……改错了怎么救回来……”
  - 新：“核心难点在于底层系统参数调优的安全性与无损可逆性：涉及电源计划、中断响应与注册表内核键值，配置失当可能导致系统不稳定。解法是在所有优化策略执行前统一导出环境快照，支持单项独立启闭与全局一键回退；修复过局部 Mutex 遭遇 GC 回收导致单实例互斥失效的缺陷，重构为静态生命周期持有。”
- **GameBoost-DLSSG**：
  - 旧：“注入完没法判断到底生效没有……解法是不再靠猜……”
  - 新：“核心难点在于跨代显卡动态链接库注入后的激活状态判定：模块加载进目标进程并不等同于被实际调用执行。解法采用「日志输出分析 + 目标进程已载入模块清单」双重证据链进行静默验证；若首选入口未激活，则自动切换备选入口 DLL（如针对特定游戏从 version.dll 动态回退至 winmm.dll 入口）确保代理正常接管。”
- **拍案**：
  - 旧：“把常规方案砍掉一半……信任问题用流程而不是承诺解决……断言钉着……”
  - 新：“核心挑战在于纯本地无服务环境下的大体量创作安全与内容一致性。建立严格的「待审草稿采纳流程」：模型生成内容隔离存放，须经作者明确确认并自动生成正文快照后方可合入；章节场景重排设计为纯函数切分与拼装，确保文本还原与原稿逐字节完全等价；设定一致性校验采用正文专属分词与实体作用域匹配，规避台词中的修辞干扰。”
- **Fluxion**：
  - 旧：“两件事最难：一是 51 项系统改动要「真的生效」……只核验不给旋钮……”
  - 新：“核心挑战在于 51 项底层优化项的状态真实回读与无损可逆，以及老旧架构下帧生成代理链路的精准接管。解法是建立「执行前快照备份 + 状态四档回读验证（已生效 / 未生效 / 待确认 / 需处理）」机制，对高危硬件级改动仅提供状态诊断而不开放激进调整；帧生成端引入进程模块与运行时日志双重校验，支持失败后自动切换接管入口。”

### 2.2 规格详情正文（`details`）去假口语
- 规范专业术语：
  - “秒搜（只读，不动你的文件）” → **“只读检索与多维匹配”**
  - “后台盯着新增和改动” → **“后台实时监听文件变更与增量索引”**
  - “把图里的字抄出来” → **“图片内容多模态检索（本地视觉描述与文字识别 OCR）”**
  - “换手机不丢” → **“学习进度、收藏夹与错题记录支持导出为标准 JSON 格式，便于跨设备迁移”**
  - “只读核验、不给旋钮” → **“涉及硬件稳定性的项目仅保留只读核验、不开放激进开关”**
  - “二游与 3A 不动你的远控” → **“进游戏按预设档位自适应切换系统状态，根据对局类型智能匹配策略”**

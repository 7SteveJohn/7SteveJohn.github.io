# 文章封面补全与阅读弹窗滚动位置复位 - 交付记录

## 1. 交付背景与问题根因

### 1.1 问题一：文章卡片无封面、只有大写字母「A」
- **现象**：在首页文章列表与 AI 学习模块中，文章卡片左侧统一渲染为深蓝色方块加单字母占位符「A」。
- **根因**：
  1. `posts/*.md` 大部分文章 front-matter 缺少 `cover` 字段定义。
  2. `js/app.js` 的 `articleCardHtml` 在 `art.cover` 为空时，回退渲染 `<span class="ac-fallback">${initial}</span>`，其中 `initial = (art.category || '手记').slice(0, 1)`。AI 学习系列的 7 篇文章分类均为「AI 学习」，首字母均为 "A"，导致整齐划一全部显示 "A"。
- **解决方案**：
  1. 编写 SVG 封面生成引擎 `scripts/gen-covers.mjs`，为全站 17 篇技术文章和 AI 学习文章定制高对比度、深空代码风格矢量封面（16:9 / 640x360），包括清晰的大标签、几何视觉图案与发光点缀，结合已有 WebP 封面实现 19 篇文章 100% 独立封面覆盖。
  2. 批量回写 `posts/*.md` 的 `cover` 字段，并通过 `build-articles.mjs` 重新编译出带有完整 `cover` 属性的 `js/articles.js`。
  3. 在阅读弹窗正文顶部同步注入 16:9 封面 Hero Banner，提升阅读体验沉浸感。

### 1.2 问题二：文章阅读看了一半，打开下一篇默认仍处于一半位置
- **现象**：读者打开某篇文章阅读下滑至中部，关闭弹窗或点击下一篇时，新文章没有从顶部开始，而是停留在上一篇的滚动位置。
- **根因**：
  1. **双层可滚动容器设计冲突**：`index.html` 中外层遮罩 `#article-modal` 带有 `overflow-y-auto`，内层 `#article-modal-content` 也带有 `max-h-[85vh] overflow-y-auto`。当用户在弹窗外侧 padding 或部分设备视口下滚动时，实际产生滚动偏移的是外层 `#article-modal`。
  2. **复位逻辑盲区**：旧代码仅在 `modalContent.scrollTop = 0` 做单点重置，从未复位 `#article-modal.scrollTop`。
  3. **关闭未清理**：`animateModalClose` / `closeArticleModal` 在关闭时从未重置两级容器的 `scrollTop`。
  4. **异步渲染时序**：Markdown 渲染器通过 `ensureMarkdown().then(...)` 异步置换 DOM，内容高度暴增时没有二次触发位置钉顶。
- **解决方案**：
  1. 封装统一的 `resetArticleModalScroll()`，同时复位 `#article-modal` 和 `#article-modal-content` 的 `scrollTop = 0`，并利用 `scrollTo({ top: 0, left: 0, behavior: 'instant' })` 确保即时生效。
  2. 在 `openArticleModal` 入口、`renderNow` 渲染完毕、移除 `.hidden` 后的 `requestAnimationFrame` 微任务、`ensureMarkdown` 异步渲染完成回调中，均严格调用复位。
  3. 在弹窗关闭（`closeArticleModal` / `animateModalClose` 动画结束隐藏时）提前彻底归零。
  4. 升级阅读进度条监听器 `initArticleProgress` 与目录监听 `initTocSpy`，同时兼顾外层容器与内层容器滚动事件。

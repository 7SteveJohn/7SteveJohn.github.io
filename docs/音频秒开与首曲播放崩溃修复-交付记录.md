# 音频秒开与首曲播放崩溃修复交付记录

## 1. 问题根因排查 (Root Cause Analysis)

用户反馈：「每次重新进这个页面，歌曲都要加载半天。而且我刚才试了试，第一首歌直接放不了」。
通过在 Headless Chrome（带激活 Service Worker 与持久化存储）环境下进行全链路抓包排障，精准定位了两个致命根因：

### 1.1 第一首歌直接放不了的原因（Fatal Range Truncation）
- **致命机制**：先前的 Service Worker 预热机制引入了 `warmPartial`，仅抓取首曲前 256KB 字节存入 `?sjwarm=1` 缓存切片。
- **协议冲突与解复用器崩溃**：
  当 Chromium 的 HTMLMediaElement 播放 MP3 时，底层 `MultiBufferDataSource` 会发起开放式 Range 请求 `Range: bytes=0-`（请求从 0 到文件末尾）。
  而 Service Worker 的 `handleRange` 拦截了此请求，并返回了仅有 256KB 的预热切片 `Content-Range: bytes 0-262143/4226950`，随后直接掐断响应流。
  在 Chromium 内核中，对于未明确指定终止字节的开放 Range 请求，服务器单方面提前截断数据流会被认定为传输破损。Chromium 的 `FFmpegDemuxer` 无法获取后续帧头及末尾元数据，直接抛出底层致命异常：
  `PipelineStatus::PIPELINE_ERROR_READ: FFmpegDemuxer: data source error`，`networkState` 直接变为 3（`NETWORK_NO_SOURCE`），导致第一首歌原地报错彻底报废。

### 1.2 每次重新进页面歌曲都要加载半天的原因（Cold Cache & Empty Preload）
1. **音频完全未加入全量预缓存**：`sw.js` 的 `CORE` 清单从未包含音频，首次和重入页面的访客必须跨洋向境外 GitHub Pages 发起 4MB~7MB 的大文件请求。国内网络环境下延迟极高、带宽受限，导致缓冲时间高达 8~15 秒。
2. **初始化清空了 `audio.src`**：由于历史版本试图避开卡顿，在 `restore()` 中删除了 `audio.src` 并将标签设为 `preload="none"`。导致访客点播时，浏览器必须经历连接握手、Range 协商、流式下行等多重网络往返，白白等待半天。
3. **全量缓存被门禁拦截**：原本全量缓存需要等到歌曲播放稳定 2.5 秒后才后知后觉地发起。但因为第一首歌直接被 demuxer 报错崩溃，根本走不到 `playing`，所以首曲永远无法沉淀进浏览器持久缓存。

## 2. 解决方案与实施细节 (Implementation)

### 2.1 彻底切除有害的 256KB 伪切片，重塑标准 206 流式与全量缓存 (`sw.js`)
1. **彻底移除 `warmPartial` 与 `?sjwarm=1`**：
   - 不再向开放式 Range 投毒残缺切片；
   - 在 SW `activate` 生命周期中，主动清理所有历史残留的 `?sjwarm=` 废弃条目，避免脏缓存破坏后续播放。
2. **标准 HTTP 206 Range 零等待透传 + 异步后台全量入库**：
   - **已全量缓存**：直接由 `slice206` 从内存 `ArrayBuffer` 即时切片响应，**0ms 零网络延迟秒开出声**，且任意拖动进度条（Seek）瞬间响应；
   - **未缓存**：直接向网络发起标准 206 流式请求，收到首批数据即刻播放，绝不阻塞当前播放流；同时后台非阻塞触发 `prefetch(req.url)`，在播放的同时将完整音频静默持久化至 Cache API。
3. **SW 激活后后台静默预热首曲**：
   - 在 `activate` 完成后，利用后台空闲带宽预取 `./music/attention.mp3` 全量入库，访客二次进站或刷新时首曲已在本地硬盘，点击即播。
4. **Service Worker 版本升级**：
   - 升级至 `sevenjohn-v233`，强制全网客户端更新。

### 2.2 播放器加载流与预加载重塑 (`js/player.js` & `index.html`)
1. **`<audio id="music-audio" preload="metadata">`**：
   - 预设 `preload="metadata"`，允许浏览器就绪时长等必要音轨元数据；
2. **`restore()` 预设首曲音轨**：
   - 页面挂载时即预设 `audio.src = SONGS[current].src;`，点击播放时跳过地址赋值与重新握手阶段；
   - 协同 SW 异步触发 `prefetch-media`，全量拉取首曲；
3. **双曲预热流式体验**：
   - 当前歌曲触发 `playing` 时，立即向 SW 登记当前歌曲与**下一首曲目**的双向全量预热；
   - 访客听歌过程中下一曲已静默沉淀入库，切歌实现 0 缓冲秒切。

# 札签 cards · 移动端与全流程体验优化交付记录

> 交付日期：2026-11-16（2026-11-18 补充原地抽卡重构）  
> 责任模块：`css/cards.css`（作用域样式）、`js/cards.js`（CardsCore 核心逻辑）、`js/app.js`（首页内嵌衔接）  
> 适用场景：`index.html` 首页 `#blog` 原地拆包抽卡 + `cards.html` 独立全屏页

---

## 1. 优化背景与核心痛点

用户反馈在日常使用中「忘记给移动端进行优化了」。经实测排查，札签卷宗系统在小屏及移动设备上存在以下体验断层：

1. **卷宗架严重纵向堆叠**：桌面端原本为固定 `184px × 254px` 尺寸加 `26px` 间距（双列需 $\ge 394\text{px}$ 净宽）。在常见的 375px ~ 414px 手机屏上无法并排，自动掉落为单列垂直排布，9 卷卷宗形成超过 2500px 的超长纵向长卷，滑动手感沉重。
2. **移动端控件比例与安全区缺失**：HUD 顶栏按钮与牌堆舞台在窄屏下存在间距过宽问题；阅读页与总目抽屉在触控设备上未适配刘海屏及底部安全区（`env(safe-area-inset-*)`）。
3. **阅读页排版简陋**：此前 `.reader-body` 缺少代码块 (`pre / pre code`)、对比表格 (`table / th / td`)、引用块 (`blockquote`) 以及二级标题 (`h2`) 的样式规则，文章中的复杂 Markdown 内容在阅读弹窗中排版粗糙且表格会横向撑破视口。
4. **缺乏卷内连续阅读链路**：阅读完一札后必须点击返回收回牌堆或目录，无法在当前分类卷宗内顺畅翻读「上一札 / 下一札」。
5. **阅读进度无持久化**：已启封状态与入册小书脊仅存留在内存 `Set` 中，页面刷新后进度归零。

## 2. 具体优化方案与技术落地

### 2.1 移动端卷宗架：2 列自适应精巧网格

在 `css/cards.css` 的 `@media (max-width: 560px)` 作用域内，重塑卷宗架布局：

- **网格重构**：`.cards-scope .packs` 采用 `display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 12px;`，最大宽度限定为 380px 并居中，保证在任何手机视口下始终规整呈现为双列册页形态，告别无休止单列滚动。
- **等比微缩精致度**：
  - 卷宗尺寸自适应缩放为高度 `220px`，圆角收至 `11px`，侧面白纸厚度微缩至 `7px`；
  - 卷名字号微调至 `20px`（`top: 68px`），背景宋体大字水印微调为 `80px`（居中偏上）；
  - 上下烫印细线与收录札数按比例重新定位；
  - 封签折边与锯齿撕纹宽度调整为 `46px`；
  - 底部进度栏高度设为 `40px`，进度点阵紧凑化（间距 `2.5px`、小圆点 `4px`），签孔缩至 `9px`；
  - 「未启 N 札」红印章等比微调，视觉清秀紧凑。

### 2.2 移动端各界面与触控安全区全流程适配

- **HUD 顶栏**：内边距压缩为 `14px 12px 6px`，操作按钮缩小至 `12px` 字号与 `5px 9px` 内边距，在窄屏下不折行溢出。
- **抽卡与牌堆舞台**：自适应最小高度减少留白，底部操作提示字号与位置微调，提升单屏信息密度。
- **总目抽屉**：移动端取消外层 `18px` 间距，面板自适应展开为 `100vw` 满屏抽屉，符合触控设备的使用习惯。
- **阅读页安全区**：
  - 顶栏 `.reader-bar` 接入 `padding-top: max(10px, env(safe-area-inset-top))`；
  - 底部 `.reader-main` 接入 `padding-bottom: max(60px, env(safe-area-inset-bottom))`；
  - 左下角入册托盘 `.pile` 接入 `bottom: max(10px, env(safe-area-inset-bottom))`。

### 2.3 阅读页高保真排版系统（Rich Typography）

为 `.cards-scope .reader-body` 补全了全面的排版样式规则：

- **代码块（Code Blocks）**：
  - `pre`：固定深色背景 `#0d1117 !important`、微透明边框、圆角、内边距，开启 `-webkit-overflow-scrolling: touch` 保持流畅横向滑动。
  - `pre code`：剥离内联代码的边框与底色，还原极客编辑器语法高亮排版。
- **数据与对比表格（Tables）**：
  - 建立干净的分隔线体系，表头采用 `var(--wash)` 浅底，行间加入微妙的偶数行斑马纹；
  - 移动端适配 `display: block; max-width: 100%; overflow-x: auto; white-space: nowrap;`，确保宽表可独立横向滑动，绝不挤爆或横撑正文容器。
- **引用块（Blockquote）**：
  - 左侧 `3px` 品牌强调色 Accent 边条，微水洗底色与柔和文字颜色，提升引用段落质感。
- **层级与间距（Headings & Rules）**：
  - 增加 `h2`（21px，带细下划线）、`h4`（15.5px）与 `hr` 分割线规则，长篇深度手记章节结构更严谨。

### 2.4 卷内顺序翻阅（上一札 / 下一札）

- **DOM 结构注入**：在阅读页骨架 `SK_FULL` 正文底部追加 `<nav class="reader-nav" id="readerNav" hidden></nav>`。
- **上下文感知**：根据当前文章的所属分类获取本卷所有文章列表，计算当前序号。
- **双向导航控制**：
  - 若为本卷首篇，上一札按钮置灰禁用，文案显示「已是本卷首篇」；
  - 若为本卷末篇，下一札按钮置灰禁用，文案显示「已是本卷末篇」；
  - 若本卷仅收录 1 札，自动隐藏导航条。
- **无缝切换动效**：点击导航按钮时，自动调用 `settleAfterRead(currentA)` 保存当前文章阅读状态，并通过 View Transition（`vt`）平滑过渡到目标文章，封面重塑归位，阅读容器瞬间复位至顶部。

### 2.5 阅读状态持久化（`localStorage`）

- **存储规范**：使用标准统一键名 `'sj.cardsRead'` 存储已读文章 ID 数组。
- **启动自动恢复**：
  - `CardsCore.mount` / `build()` 时读取本地存储，为各卷宗初始化已读 Set；
  - 自动还原卷宗卡面封条撕开状态（`.opened`）、未启札数印章、底部进度条点阵亮起状态；
  - 自动向左下角托盘 `.pileRow` 重建已入册小书脊，恢复「已入册 N」统计。
- **阅读时自动归档**：在 `settleAfterRead(a)` 触发时，无感写回 `localStorage`。
- **重置功能闭环**：HUD「重置」按钮由简单的重新渲染升级为清空 `'sj.cardsRead'` 并刷新，让用户随时可重新体验开封乐趣。

### 2.6 卡包视觉重构：雅致书卷与极客档案融合风

根据用户选定的设计风格，卡包（`.pack`）实现了彻底的质感升级，摒弃了生硬的单调方框与粗糙线条：

1. **版式层次与极客元数据**：
   - 顶部左侧：增设微型等宽卷号（`VOL. 01` ~ `VOL. 09`）与分类专属英文微标（如 `SYSTEM ARCHITECTURE`、`LOCAL LLM & EDGE AI`），赋予每一卷严整的典藏序列感；
   - 顶部右侧：朱砂双线印章（`未启 · N 札`），与左侧卷号形成完美的平衡布局，杜绝遮挡碰撞。
2. **中枢标题的典雅书卷气**：
   - 采用经典宋体 Serif（`Noto Serif SC / 宋体`），配以微型分类色圆角微胶囊分割条，替代了原本死板的上下横线；
   - 副标题规范为「`卷藏 N 札`」，兼顾典雅书卷感与现代极客精密感。
3. **真实纸艺与物理材质细节**：
   - **顶部纸艺折痕（Envelope Flap）**：模拟真实信封袋盖折线与纸张投影；
   - **和纸撕口封签（Washi Seal Tape）**：封签带有微孔虚线撕缝（Perforation）与物理锯齿撕边；
   - **装订布脊边（Spine Tape）**：左缘 7px 装订胶带，带细致内嵌缝线高光与分类色彩印；
   - **档案金属扣（Brass Eyelet Rivet）**：底部右侧引入物理质感铜扣眼，与左侧的微型进度点阵相得益彰。
4. **完卷归档（Archived）反馈**：
   - 当一卷全部研读完毕后，朱砂红印沉静转换为墨灰色的「已全阅」归档戳记，形成极具仪式感的收集闭环。

### 2.7 去扑克化重构：典藏补充包压纹撕封与双面 3D 翻牌陈列架构

针对原版「单摞叠牌 + `7.2°` 手牌扇形 + 左右拖拽切牌沉底 + 开包即明牌大白板」带来的纸牌接龙/斗地主既视感，对标 *Pokémon TCG Pocket*（热压锯齿撕封 + 上四下三陈列）、*Hearthstone*（深色精装牌背悬停品质预兆 + Y 轴 3D 翻牌定格）与馆藏级金属微闪膜（Simeydotme 多层光学混合体系），完成了彻底的典藏抽卡重构：

1. **Stage 1：热压锯齿补充包（Booster Pack）与 4 拍确定性撕封编排（`build` + `openPack`）**：
   - 摒弃信封折盖（`.pk-flap`）与露头白纸条，重构为带纵向热压棱纹与锯齿下沿的顶部封条 `.pk-crimp-top`（配左右易撕 V 型缺口 `.pk-notch` 与 `SEAL · 拆封` 铭文）、裂隙细光缝 `.pk-seam-glow`、内袋深色馆藏牌背剪影 `.pk-sheet` 及底部压纹封边 `.pk-crimp-bottom`。
   - 支持**点击卡包**与**横向划过封口/上半部（`dx > 36px`）**双触发拆封。
   - 4 拍 WAAPI + CSS 协同撕封时间轴（总长 `530ms`，免疫系统 `prefers-reduced-motion: reduce` 误报）：① `0ms` 邻包退场聚焦、目标包微压聚光，`.pk-seam-glow` 锐利细光缝自左向右划穿；② `115ms` 挂载 `.is-ripped` 露出锯齿裂口，`.pk-crimp-top` 向右上卷曲抛飞；③ `160ms` 内袋 3 枚深色牌背剪影错峰上浮探出；④ `245ms` 外层封套向下滑落消散，`530ms` 从袋口精确屏幕坐标 `(origin.cx, origin.cy)` 破封飞入陈列阵位。
2. **Stage 2：自适应 0° 端正典藏列阵（Showcase Stage Formation，`buildDeck` + `dealIn`）**：
   - 彻底移除 `cycleAway` 切牌沉底、`jitter` 随机歪斜、`spread` 侧扇、`fanBtn` 摊开切换与 `7.2°` 手牌弧扇；舞台容器 `#deck[data-count]` 改为居中弹性陈列阵型（`1` 张单核英雄位、`2` 张双子位、`4` 张桌面单行横排 / 移动 `2×2`、`7` 张桌面 `4+3` 居中双排 / 移动双列末张居中）。
   - 智能卷内排序：系列卷（如 `AI 学习` 含「一、二…」章节序号）严格按 `一 → 七` 正序从左至右入阵；常规技术卷按日期倒序（最新居首）入阵。
   - `dealIn(origin)` 逐卡测量静止态 `getBoundingClientRect()`，以 `0°` 端正姿态配合厚重卡纸单次微过冲弹簧 `SPRING_SETTLE`（`520ms`，`48ms` 错峰）落定。
3. **Stage 3：双面 3D 馆藏卡牌、两段式翻牌揭晓与金属闪膜视差（`ensureCard` + `flipCardReveal`）**：
   - **Preserve-3D 防拍平隔离**：`.card-rotator > .card-flipper > (.card-front + .card-back)` 全链路零 `overflow: hidden` 与零 `backdrop-filter`，圆角裁切严格下沉至平面层 `.card-clip`；正面定位于 `rotateY(0deg)`、牌背定位于 `rotateY(180deg)`，揭晓落定后处于纯平面 `0deg`，确保中文亚像素字体锐利不发虚且 `view-transition-name` 变形不断链。
   - **深色馆藏星盘牌背与品质分级**：亮暗模式统一采用深色矿物板岩底配双线画框、四角斜切饰纹与几何星盘徽记；依据真实内容深度划分 `data-rarity="foil"`（`≥ 9 分钟` 深度长文及首页精选代表作）与 `standard`，悬停未翻牌背触发差异化边缘辉光预兆。
   - **TCG 五段式典藏正面**：消灭原版空白肚皮，依次排布顶栏铭牌（分类圆点 + `✦ FOIL · NO.XX`）、画框式插画视窗（配 `.cf-art-foil` 斜纹微棱镜闪膜，已读绝不置灰）、技术词条与阅读时长栏（`.cf-typebar`）、双行标题与左饰线摘要铭文框（`.cf-lore`，移动端双列窄卡自动降噪收隐）、底栏日期与召唤指引（`[data-cta]`）。
   - **5 关键帧 3D 翻牌与自动闪膜掠光**：点击未翻牌背执行 `580ms` WAAPI 翻牌（`180° → 186°` 微压蓄力 → `90° scale(1.08)` 凌空跃起 → `-7.5°` 弹簧过冲 → `0°` 落定），中点自动扫过 `.card-reveal-sheen` 斜向流光并驱动 `500ms` 自动金属闪膜插值（兼顾桌面与触控端），翻开当次不直跳弹窗；再次点击已翻开正面执行 `170ms` 提牌反馈后打开正文阅读（卡片保留原位，不抽走不重排）。
   - **桌面 `rAF` 3D 微倾与触控非阻塞横搓**：桌面鼠标悬停追踪 `--rx / --ry / --px / --py / --hyp` 驱动立体微倾与 `mask-composite: exclude` 金属外框反光；移动端保持纵向滚动零阻塞，支持在已翻开卡面上横向轻搓检视闪膜。
4. **双层持久化与无痛复访状态机（`sj.cardsRevealed` + `sj.cardsRead`）**：
   - 独立持久化已翻开集合 `sj.cardsRevealed` 与已读集合 `sj.cardsRead`（旧存档已读自动视为已翻开）。已翻开过的卡片复访时直接正面朝上入阵，单击即读零打扰。
   - HUD 动态切换：存在未翻卡牌时高亮显示 **`✦ 全部翻开`**（`#flipAllBtn`，`65ms` 波浪连翻）；本卷全数翻开后自动切换为 **`↺ 重新覆牌`**（`#reflipBtn`，支持随时执行 `0° → 90° → 180°` 覆回牌背重玩翻牌仪式，且绝不清空 `sj.cardsRead` 已读进度与入册小书脊）；独立页 `#resetBtn` 一键清空双集合。
   - 总目抽屉兼容：`cards.html` 的 `.cat-grid` 复用 `.card` 节点并压平为横条索引态，开闭抽屉与阅读页返回均无缝还原列阵状态。

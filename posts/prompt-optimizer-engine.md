### 问题：改个提示词不想联网调 API

市面上很多提示词助手，背后都要你填云端 API Key。但很多本地任务的提示词里带着私有格式和业务字段，把这些传给第三方我不接受；而且大模型一润色，经常自作主张加一堆废话指令。

其实大部分人写提示词卡壳，只是漏了输出格式、缺角色、或者写了自相矛盾的要求（比如既要详细展开又要求极其简短）。这种骨架层面的结构问题，根本不需要大模型，几行正则就能挑出来。

### 方案：纯本地单页做静态排查

写了个纯本地单页，不联网、不调任何模型，靠 JavaScript 规则做检查：
- **10 项要素体检**：查角色、指令、格式约束、示例等骨架有没有写全，缺项给出扣分和填空提示。
- **互斥冲突识别**：内置 6 组矛盾词表（如“详细 vs 极简”、“只要结果 vs 列出推导过程”），同时出现就报预警。
- **格式清理与修复**：分安全级（补闭合围栏、中英文空格规范，一键直接改）和确认级（否定句转肯定句、多动词拆步骤，弹窗看 diff 确认后改）。
- **支持行豁免**：代码块或者特定句式不想被报错，行尾挂个 `(po-ignore: ...)` 标记就能跳过指定规则。

### 踩坑

1. **编辑距离分不清业务意图**：早期想用编辑距离抓输入时的轻微笔误重复。实测发现“每段不超过 50 字”和“每段不超过 60 字”在字符上只差 1，但这是完全不同的业务要求。纯规则在短文本上分不清，只能作废，重复行只做 100% 精确匹配。
2. **高频词表抓不住套话**：想通过抽象词密度来提示“指令空转”，结果发现具体指令里的抽象词有时候比套话还多。空洞是语义层面的事，轻量词表硬套误报率极高，果断砍掉。
3. **全角字符混排**：从不同聊天软件复制进来的文本，常带零宽空格或全角数字，会导致后续正则切词全部失效，进引擎前必须先跑一轮清洗。

### 结论

规则引擎的用处就是当个 Linter：模型推理前，花几毫秒把格式漏洞和脏字符挑干净。它读不懂深层意思，也不用指望它帮你写出惊艳的文采；但胜在完全本地运行，断网能用，不泄露数据。

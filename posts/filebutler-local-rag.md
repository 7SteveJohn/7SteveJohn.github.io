### 问题：想「问文件」，但文件不能出门
很多工具说自己集成了 AI，背后都要你填一个云厂商的 API Key。对个人文档、发票、私有代码来说，把明文实时传给第三方，这个代价我不接受。

于是目标变成两条：一，计算和索引全在本机；二，体验不能因为「本地」就打折——搜索要快，整理要能反悔。

### 方案：快的归快，慢的归慢
- **文件名 / 长文本 / 语法匹配**：走 SQLite 内置 FTS5 倒排，毫秒级出结果，支持 `ext:pdf`、`size:>100mb`、`dm:本周` 这类语法。
- **语义问答**：用 bge-m3 建稠密向量库，**放在后台空闲时增量建**，不挡着用户干活。
- **所有整理动作三步走**：规则或模型出方案 → 生成移动计划 → 用户勾选确认 → 写事务日志再执行。不满意就按批次整体回滚。
- **Ollama 不可用时自动降级**：退回规则整理 + 关键词搜索，功能变少但程序不崩。

### 踩坑
1. **别在启动时建向量库。** 一开始就全量索引，机器会被拖住，首次体验直接劝退。改成后台空闲增量建，新文件到了再补。
2. **语义检索不适合精确匹配。** 搜文件名、扩展名、大小这类精确条件，向量检索反而找不准——先让 FTS5 命中，再用语义排序。
3. **「撤销」不是把操作反过来做一遍。** 移动可能覆盖同名文件、目标盘可能写满、期间文件可能又被改过。所以回滚必须基于事务日志，不能靠重算。
4. **文件监控事件会抖。** watchdog 全量监听大目录时，一次复制能刷出上百个事件，得去抖 + 批量合并。
5. **本机服务只绑 127.0.0.1。** 缩略图这类临时服务，别顺手监听 0.0.0.0——那就是把本地文件挂到局域网上了。

### 结论
端侧 AI 的难点不在模型，在工程：**把快和慢分开处理，把「可撤销」当前提而不是补丁**。断网能用只是这套设计的副产品。另外一条更重要的：本地模型要当成**可选项**来设计，它挂了程序应该降级，不是崩溃。
